   137→   137→## Session: Bug Fix - Strict Alternating Raid Sequence & Turn Control
   138→   138→
   139→   139→### Current Project Status
   140→   140→- Next.js 16 app with Kabaddi live scoring system
   141→   141→- Teams Leaderboard feature completed in previous session
   142→   142→- Live scoring had critical bugs with turn rotation, do-or-die, and state management
   143→   143→
   144→   144→### Completed Modifications
   145→   145→
   146→   146→#### 1. Fixed `addEvent()` in store.ts — No longer blindly flips raidQueue
   147→   147→**Bug**: `addEvent()` always flipped `raidQueue` regardless of event type. This meant timeouts, substitutions, cards, and other non-raid events would incorrectly change whose turn it was to raid.
   148→   148→**Fix**: Only raid-ending events (raid_point, tackle_point, super_tackle, empty_raid, bonus_point, do_or_die_raid, super_raid, self_out) now flip the turn. Non-raid events (all_out, substitution, timeout, yellow_card, red_card, green_card) preserve the current raidQueue.
   149→   149→
   150→   150→#### 2. Fixed `getRaidQueueFromEvents()` — Added missing event types
   151→   151→**Bug**: `super_raid` and `self_out` were not in the `raidEventTypes` list used to determine the raid queue from event history. This caused incorrect turn calculation when these were the last events.
   152→   152→**Fix**: Created `RAID_ENDING_EVENT_TYPES` constant that includes all raid-ending events including `super_raid` and `self_out`.
   153→   153→
   154→   154→#### 3. Added team-specific Do-or-Die tracking (`doOrDieTeamId`)
   155→   155→**Bug**: `isDoOrDie` was a global boolean, but do-or-die applies to a specific team's next raid. If Team A earned a do-or-die, it would incorrectly show for Team B's next raid too.
   156→   156→**Fix**: Added `doOrDieTeamId: string | null` to `ActiveMatch` interface. Updated `setDoOrDie()` to accept an optional teamId parameter. All UI checks now verify both `isDoOrDie` AND that `doOrDieTeamId` matches the current raiding team.
   157→   157→
   158→   158→#### 4. Added strict turn lock with visual indicators
   159→   159→**Changes**:
   160→   160→- Added `isTurnTransitioning` state that briefly prevents raider selection after a raid ends (800ms lock)
   161→   161→- Added "RAID" badge (with Swords icon) on the raiding team's info bar
   162→   162→- Added "DEF" badge (with Shield icon) on the defending team's info bar
   163→   163→- Added "DEFENDING" label at the bottom of the non-raiding side
   164→   164→- Added "TAP TO RAID" label on the raiding side (existing, kept)
   165→   165→- Added turn transition overlay showing "[Team]'S RAID" with animated arrow when turn switches
   166→   166→- Do-or-die flame 🔥 only shows when it's the affected team's turn to raid
   167→   167→
   168→   168→#### 5. Clean state reset per raid
   169→   169→**Changes**:
   170→   170→- After every raid, ALL raid state is completely cleared: raider, raidResult, selectedDefenders, bonusPoint
   171→   171→- Turn transition lock activates to prevent immediate selection by the next team
   172→   172→- Half-time transition now also resets `isTurnTransitioning`
   173→   173→
   174→   174→#### 6. Proper evaluation order — Do-or-Die/Super Tackle/All-Out before turn swap
   175→   175→**Verified**: The current order is correct:
   176→   176→1. Create events for raid result (including all-out, super tackle auto-detection)
   177→   177→2. Evaluate do-or-die logic (set/clear per team)
   178→   178→3. Call `addBatchEvents()` which triggers recalculation AND raidQueue flip
   179→   179→4. Reset raid state
   180→   180→5. Activate turn transition lock
